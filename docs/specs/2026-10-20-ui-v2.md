## 1. 这次改了什么

一句话：门户从「我的页面 + 创意市场两个 tab」变成了「左侧栏 + 四个平级的地方」，
控制台从九屏收成五屏，手机壳的底栏从四格平分变成「一颗圆钮 + 一粒胶囊」。

视觉上整套色值也换了一轮：画布从冷白 `#fcfcf8` 换成暖米 `#faf8f3`，品牌橙从
`#fb923c` 加深到 `#ee5c2a`，正文色从带蓝的 `#1c1f23` 换成带褐的 `#292724`。
变量名一个没动，所以没改过的屏也跟着换了皮——这正是当初把色值全收进
`packages/ui/src/tokens.css` 的目的。

## 4. 新增的后端

改版稿要求的事实，库里一条都没有，这次一并补上（迁移 `0032`、`0033`）：

| 能力 | 表 | 接口 |
|---|---|---|
| 喜欢（页面） | `app_likes` + `apps.like_count` | `POST/DELETE /apps/:id/like` |
| 评论（页面） | `app_comments` + `apps.comment_count` | `GET/POST /apps/:id/comments`、`DELETE /comments/:id` |
| 评论点赞 | `app_comment_likes` + `app_comments.like_count` | `POST/DELETE /comments/:id/like` |
| 关注 | `user_follows` | `POST/DELETE /authors/:name/follow` |
| 动态 | `posts`、`post_likes`、`post_comments` | `GET/POST /posts`、`DELETE /posts/:id`、`POST/DELETE /posts/:id/like`、`GET/POST /posts/:id/comments` |
| 兴趣 | `users.interests` | `GET/PUT /me/interests` |
| 作者主页 | — | `GET /authors/:name`（资料 + 他公开的作品，一次拿齐） |
| 下架/重新上线 | — | `POST /apps/:slug/status` |
| 确认并发布 | — | `POST /agent/publish` |

几条贯穿的做法：

- **喜欢/关注用 POST + DELETE 两个动词，不用 toggle**。手快点两下，toggle 会
  互相抵消成「点了没反应」。
- **计数一律重算**（`SET x = (SELECT count(*) …)`），不是 `+1/-1`。重复点、并发、
  日后手工改数据都不会把计数器带偏。
- **看不见的页面一律回 404，不回 403**。这些接口能被拿着 id 遍历，403 等于回答了
  「这个 id 存在」。
- **社交动作不写审计**。那张表是「发布记录」那一屏的数据源，点赞混进去会把真正
  要查的发布改动冲掉。

### 4.1 `POST /agent/publish` 为什么要存在

原来的 `/agent/confirm` 只是「人点头了」：核销 token、写一条审计，然后回一句
「请用 ai-deploy up 或 MCP 的 deploy 工具把工作区发到 /xxx」。在手机壳里说得通
——那边的人本来就是回电脑上接着用 CLI 的。

改版稿的「创建」屏不是这样：人在浏览器里说一句话、看着预览、点「发布到我的
空间」，这一下之后页面就该在线。所以把最后一步接上：核销 token，然后把工作区
当产物走一遍正规发布链路（扫描、base path 校验、注入 chrome、落 release、切软
链），和 CLI 发布一字不差。二次确认没有被绕过——token 仍由 Agent 的
`request_deploy` 发起、由人这一次点击核销，一次性。

## 4.9 创建页的模型与思考档位

模型通道是**管理员配的**，不是用户能添的：`AGENT_MODELS` 列出平台允许选的
几条，一条写成 `id|给人看的名字|倍率`，逗号隔开；`AGENT_EFFORT=1` 才认思考
档位。`/agent/status` 把这两样一起返回，创建屏照着画。

```
AGENT_MODELS=gpt-5.6|iSpace Auto|0.4x, claude-sonnet-5|Claude Sonnet 5|1x
AGENT_EFFORT=1
```

两处是故意的：

- **只配了一条通道、又没开思考时，仍旧是一个灰色的名字**，不画下拉。下拉里
  只有一行、点了还是它——那种菜单比没有更让人疑心。
- **前端传来的 `model` 只认白名单**（`createEngine` 里 `models.find(...) ?? models[0]`）。
  它是直接发给网关的字段，原样转发等于把「用哪个模型」的开关交给任何会发
  HTTP 的人。思考档位同理：平台没开就不往网关发，但也不报错——用户没做错
  什么，不值得让一次生成失败。

## 4.95 创建 · 工作台（2026-10-20 第二版稿）

设计师把「创建 · 生成」整屏换成了「创建 · 工作台」。这一屏现在分三段：

| 段 | 这一屏在做什么 | 真的假的 |
|---|---|---|
| 问 | 两道选择题：走不走设计扇出、主要在哪儿看 | **平台的固定脚本**，不是模型问的 |
| 扇出 | 并行跑 N 个 Design Agent，各出一版自包含 HTML | 真的 N 个模型会话（`/agent/fanout`） |
| 做 | 照挑中的那一版做真页面 | 和原来一样走 `/agent/ask` |

几处判断：

- **开头那两道题由平台问，不由模型问。** 它们决定的是这一屏接下来怎么走，
  不是页面长什么样。让模型问要多烧一轮，还会出现「模型忘了问」。代码里
  这两道（`PLATFORM_ASKS`）和模型问的那种（`ask_user`）是两类数据，画成
  同一种卡片，但来源不混。
- **模型也能问**：新增 `ask_user` 工具。调它会**结束这一轮**
  （`stopReason: 'ask'`）——问题摆出去了就该等人，继续往下写代码等于没问。
  问题不成形（没问题、选项不足两个）时当没问过，模型自己定。
- **扇出是全平台唯一一处一次请求跑多个模型会话的地方**，N 倍开销。所以：
  条数由 `AGENT_FANOUT_N` 配（默认 6），每个方向的轮次上限压到 4，而且只有
  用户在第一道题里明确选了「生成六版视觉设计」才会走到。别把它变成默认路径。
- **草案不发布**：扇出写在工作区的 `_fanout/<run>/<方向>/index.html`，发布时
  按「下划线开头的顶层目录」整个排除（`scratchFilter`）。它们在工作区里是因为
  预览要能直接看到，但它们不是这个页面的一部分。
- **右栏三页**：预览 / 代码 / 设计。「代码」是只读的——摆一个能编辑的编辑器，
  等于让人和模型同时改同一份东西，而谁都不知道对方改了什么。
- **外壳让位**：进工作台时 Shell 的顶栏收起、滚动交给这一屏自己管
  （`chrome=false`）。⚠️ 切换 `chrome` 不能改变 children 在树上的位置，
  否则 React 会把整屏卸载重挂，刚说的那句话和刚开的会话全丢——实测踩过。

侧栏跟着改了三处：「创建」改名 **iDo**（16px/700，比另外三项大一号重一档）、
删掉底下那颗「一句话做页面」的大按钮、选中项从淡橙底改成**实心橙**
（`--nav-on-bg` 等三个 token，控制台侧栏跟着变）。

## 4.96 Agent 能生图（2026-10-20）

新增 `generate_image` 工具：模型写页面时自己调它出插图/封面，图落进工作区，
页面用相对路径引用。**生图通道和对话模型分开配**（`AGENT_IMAGE_MODELS`）——
两张单子里的 id 不能混：对话模型没有生图语义，生图模型驱动不了工具集，混进
去的后果是用户在下拉里选了它、这一次生成当场失败，看起来像平台坏了。

没配生图通道时：工具不挂、系统提示里不提、`/agent/status` 的 `imageModels`
是空数组。三处是同一个开关的三面——说了能画就得真能调，否则模型会写一个
`<img src="assets/hero.png">` 然后发现没有那个工具，页面上留一个裂图。

2026-10-20 在公司网关（vibe.soyoung.com）上实测到的：

- 响应是 `data[0].b64_json`（PNG）。`url` 形态也收着，换网关时不至于整条断。
- **size 不起作用**：同一个模型传 `1024x1024` / `1536x1024` / `1024x1536` /
  `auto`，回来的是 1254×1254、1312×1199、1312×1199、1312×1199——尺寸由网关
  自己定，同样参数两次还未必一样。所以工具**不给 size 参数**（摆一个按了
  没反应的旋钮比没有更糟），系统提示里明确要求页面用 CSS 兜住。
- 一张约 2 MB。每次请求最多 8 张（`MAX_IMAGES_PER_SESSION`，计在**请求**上
  而不是会话上：会话活一小时，按会话算的话说十句就能生八十张）。
- `agnes-image-2.5-flash` 在这个网关上打不通，**而且不是参数问题**：按官方
  文档（<https://wiki.agnes-ai.com/en/docs/agnes-image-25-flash.md>）补齐
  `size: "2K"`、`ratio`、`return_base64` 之后，`/images/generations` 仍然回
  同一句「images endpoint requires an image model」——网关在**路由那一层**
  就拒了，没到参数校验；`/chat/completions` 与 `/responses` 则是 502。
  同一时刻 `agnes-2.5-flash`、`agnes-3.0-flash`（文本）都是 200，`gpt-image-*`
  也正常，所以是这个模型在网关上没被登记成图片模型，得网关那边改。
  **所以没有配进去**——配一个已知打不通的 id，等于把一次必然失败的计费调用
  摆在用户面前。代码里 `dialectFor` 已经按官方文档备好了 agnes 系要的字段，
  等网关通了只需把 id 加进 `AGENT_IMAGE_MODELS`，但那一支**至今没能实测**。

  > Agnes 与 gpt-image 的接口方言不同，值得记一笔：Agnes 的 `size` 是必填的
  > 档位名（`1K`/`2K`/`3K`/`4K`），宽高比另给 `ratio`，要 base64 发顶层
  > `return_base64`；而 gpt-image 系的 `size` 发了也白发。统一发一套的话，
  > 两边各错一半。

扩展名按**实际格式**改正，不听模型的：它常写 `.jpg` 而网关出 `png`，发布后的
站点带 `nosniff`，那时就是一个裂图，而且离生成已经很远，没人会想到是扩展名。

## 5. 对稿的偏离，以及为什么

| 稿上 | 实现 | 理由 |
|---|---|---|
| 卡片与详情是截图（`image-slot`） | 详情页与为你推荐装的是**真页面**（iframe） | 设计文档跑不起真页面才用占位图；我们手上有真东西。`sandbox` 给脚本和表单但**不给** `allow-same-origin`——两者同时给等于没有沙箱，被预览的页面就能借平台的 origin 读写平台接口。代价是取数的那部分会显示自己的空态，所以旁边始终留着「打开页面」 |
| 详情页事实表有「数据」「外部接口」两行 | 不摆 | 库里没有「这个页面用了哪几张表、连了哪个上游」。编一行出来会被当成真的；真要有，得先在发布时把依赖记下来 |
| 工作台「代码」页可编辑 | 只读 | 人和模型同时改同一份文件，谁都不知道对方改了什么。想改哪里在左边说一句 |
| 扇出卡片上有收藏、下载、+ 三个动作 | 只有「用这一版」 | 收藏夹和下载都还没有东西接；留着按钮点了没反应，比没有更糟 |
| 工作台头部有历史、前进、更多三个按钮 | 没有 | 会话存在内存里（见 routes/agent.ts 的 NOTE），没有"上一次"可翻 |
| 创建页「添加内容」第一项叫「上传文件」 | 叫「上传图片」 | `/agent/ask` 收的就是图片（`images`）。另外四项按稿子都在，点了说一句它将来是什么——设计稿里它们也只是弹提示 |
| 创建页进度是四步固定文案 | 进度是 Agent 真正调的工具 | 编四步假进度条，等于把「正在发生什么」换成一段动画 |
| 控制台「接入 AI」是一张「整段复制给 AI」的卡 | 没有照搬 | 屏幕下面「一键接入」做的是同一件事，而且那段话带真实令牌（这个平台的 MCP 要 Bearer 认证）。摆两段只会让人不知道该复制哪一段 |
| 发布记录展开后有带行号的源码片段 | 只写规则名、位置和下一步 | 审计表里存的是规则名和位置，不存命中的源码——存了等于把密钥又留一份 |
| 手机登录页顶上是封面拼贴 | 同色系的色块 | 那些封面要登录才拿得到（`/marketplace` 要会话）。构图一致，但不假装展示不存在的内容 |
| 手机「我」页有草稿箱 | 没有 | Agent 会话存在内存里（见 `routes/agent.ts` 的 NOTE），重启即丢，没有「草稿」这个东西可列 |
| 侧栏「常用」是手工置顶 | 最近更新的三个 | 平台没有置顶这件事。真要有，得先加一张表 |

## 6. 已知的空缺

- **移动端没有在真机/模拟器上跑过**。typecheck 与 Metro 打包（931 模块）通过，
  但这个环境里没有可用的原生构建。
- **`/agent/publish` 的「令牌 → 发布」那一段没有自动化用例**。令牌只在 Agent 调
  `request_deploy` 时生成，而那要一条真的模型通道；把 pending 表挖个口子给测试
  写，等于为了测试在发布链路上开一扇侧门。闸门部分（没登录、令牌不对、入参不
  合法）有用例，见 `agent-publish.test.ts`。
- **分组（app_groups）成了只有控制台在用的功能**。新门户的「我的作品」不按分组
  展示，而分组管理还留在「页面与版本」屏底下。要么给它找个新用处，要么删掉。
- **创建屏在发布前没有预览**这件事已经补了：右栏现在装的是**工作区实时预览**，
  模型每写完一个文件就刷一次，页面报的错会回流到对话里（点「让它修」才真的发出去）。
  方案与落地记录见
  [2026-10-20-preview-runtime.md](2026-10-20-preview-runtime.md)——其中工作区实时
  预览与预览取数令牌两层已落地，**真运行时容器（容器里跑 Node/Python）仍待拍板**。
  沙箱策略与本文件 §5 那条一字不差：给 `allow-scripts allow-forms`、**不给**
  `allow-same-origin`；预览另外多一道 `Content-Security-Policy: sandbox` 响应头，
  这样把预览地址复制到新标签页直接打开时也仍在沙箱里。
