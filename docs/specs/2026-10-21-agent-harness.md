## 1. 按页面分工作区

### 1.1 布局

```
/srv/workspaces/{username}/{会话 id}/   一次「创建」一个工作区
/srv/workspaces/{username}/legacy/     改版前那个"每人一个"的工作区，原样搬进来
/srv/workspaces/{username}/.ispace/    平台自己的：layout.json（布局标记）、snapshots/
```

### 1.2 为什么目录名是会话 id，不是 slug

任务原话是 `{slug 或会话 id}`。选了会话 id，因为：

- **开工时还没有 slug**。它要等模型 `request_deploy` 才定下来，而工作区在那之前就得存在
  ——预览、设计扇出都要往里写。
- **按 slug 命名就得在发布那一刻改名**，而那一刻预览会话、Agent 会话、前端手里的地址都指着
  旧名字，每一处都要跟着换。
- **slug 会撞旧目录名**：改版前的工作区根目录里就有 `assets/`、`css/` 这类目录，一个叫
  `assets` 的页面会被当成那个目录。

slug → 工作区的对应记在会话表里：`agent_sessions.slug`，**发布成功之后**才写。手机壳里说
「改 /zhoubao/」时按它找回当初那个工作区（取最近一条）。

### 1.3 会话 → 工作区的规则（`SessionWorkspaces`）

对话、预览、扇出、代码页、撤回、发布全问这一个地方，说法只有一份：

| 情形 | 落到哪个工作区 |
|---|---|
| 新会话（创建屏开工调 `POST /agent/session`，或手机壳第一句） | 新工作区，键就是会话 id |
| 带 `targetSlug` | 最近一次把它发布出去的工作区 → 没有就 `legacy` → 再没有就会话自己的 |
| 带一个会话表里没有的 id | `{username}/{id}/` 还在就用它（记录过了保留期被清掉）→ 不在就是改版前的会话，接回 `legacy` |
| 不带会话 id 的老客户端 | 这个人最近在做的那个 → 没有就 `legacy` |
| 手机壳中途换了 `targetSlug` | 同一条会话切到那个页面的工作区，并在这一句前面告诉模型"工作区已切换" |

令牌（`request_deploy` 签的）里记着签发那一刻的工作区，发布发的就是它——人同时开着两个
创建屏时，点哪个的发布就发哪个。

### 1.4 存量：搬，不删，也不猜

改版前根目录里直接就是文件。新布局下根目录里只该有工作区目录，于是**第一次访问时**把原有的
全部东西原样搬进 `legacy/`（`Workspaces.ensureLayout`，每人一次、幂等）：

- 一个字节都不删。`layout.json` 里记着搬了哪些东西，出问题时人工对账。
- 不能就地留着：新工作区和旧文件混在同一层，分不清 `assets` 是文件夹还是工作区。
- 不能按 slug 拆：单工作区时代所有页面的文件叠在一起，拆不开。
- 中途崩溃能接着搬：先挪进 `.migrating/`、写标记、再改名成 `legacy`；哪一步断了下次都认得出来，
  不会把 `legacy` 当成旧文件再套一层（有用例钉住）。

"人的东西看起来没消失"靠两条兜底（见 1.3 表）：刷新前开着的工作台带着旧会话 id 回来 → 接回
`legacy`；改一个从没在新布局下发布过的页面 → 落到 `legacy`，和改版前一样。

已发布的页面不受影响——它们在 `/srv/sites`、`/srv/releases`，和工作区无关。

## 2. 补丁式编辑与搜索

- **`edit_file`**：`old_string` 必须逐字一致且**在文件里只出现一次**；出现多次报错并给出行号，
  让模型多带上下文，确实要全换就设 `replace_all`。替换第一处等于替它猜改哪一处——每张卡片都是
  `<div class="card">`，猜错了改坏的是别处，而它自己不会发现。没找到时认得出两种常见原因并分别说：
  只差空白（缩进/换行），或第一行对得上、后面对不上（原文已被改过）。改完回一小段带行号的结果供确认。
- **`search_files`**：JavaScript 正则，结果条数上限 80，默认跳过 `node_modules` 与顶层 `_` 草稿。
  deploy-service 是单线程的，一个灾难性回溯的正则会卡住所有人：拒绝嵌套量词（`(a+)+` 这类），每行只取
  前 2000 字符匹配，单文件超过 1 MB 不搜。
- **`copy_file`**：用户附的文件在 `_uploads/` 下不会跟着发布，要用进页面（头图之类）得显式拷到 `assets/`。
- 安全边界全部复用 `safePath`。系统提示里写明：小改用 `edit_file`，新文件或整页重写才用 `write_file`。

## 3. 发布前自检

起因：线上 zongkelong/tianqi 写了 `innerHTML = 变量`，到用户点发布才被拦下，模型本可以自己改掉。

- **"同一套"落到字面上**：`preflight()` 每一步都调发布链路用的同一个函数——拷进暂存用同一个
  `scratchFilter`（`_fanout` 不算产物），认产物根用同一个 `resolveArtifactRoot`，扫描用同一个
  `scanFiles`，根绝对路径与 `checkBasePath` 同一条正则（新加的 `basePathFindings` 只是把行号找回来）。
- **不跑 gitleaks**：要起子进程、可能十几秒，自检会被调好几次。它是第二道，发布时照跑。
- 输出 `文件:行号:规则:建议`。建议来自 `scanner.adviceFor`——只给规则名的话，模型会做最省事的事：
  删掉那行，或换个写法骗过正则（`el['inner'+'HTML'] = x`），问题原样还在。
- 路径换算回相对工作区：产物根可能是 `dist/`，扫描器报的是相对产物根的路径。
- **`request_deploy` 时再跑一遍，没过不签令牌。** 这一条超出了"在提示里要求"：提示只是请求，模型
  会忘；不落成硬的，用户照样会拿到一个点下去才被拦的发布按钮。

## 4. 会话落库与上下文压缩

- 表 `ispace.agent_sessions(id, user_id, workspace, slug, messages jsonb, …)`，迁移 0034，服务启动时自动跑。
- `messages` 不含 system（每次按当时的连接器、预览状态重拼），不含图片字节（模型当轮看过了，存下来
  只会让表膨胀、续接时重新计费）。保留 30 天，工作区文件不受影响。
- 同一条会话不许并发两句：每句开工前拍快照、结束后存历史，交叠的话撤回会退到奇怪的地方。
- 写 jsonb 一律 `sql.json(...)`（`routes/events.ts` 顶上那段踩坑记录），有真库用例钉住存进去的是数组。

**压缩**（`compact.ts`，每次要模型输出之前检查，默认预算 16 万字符，`AGENT_CONTEXT_CHARS` 可调）：

1. 裁剪——早先几轮的工具结果只留开头，`write_file`/`edit_file` 参数里的大段文本换成「略去 N 字」。
   文件本身在工作区里，要用随时能再读。
2. 摘要——还超就让模型把更早的对话写成前情提要，替换原文。
3. 硬截断——摘要失败时按轮整轮丢掉最早的，留一句说明。宁可忘掉开头，也不能让这一轮直接 400。

最近两轮永远原样；工具调用和它的结果永远不拆开（网关见到孤立的 tool 消息会 400）。**不超预算一个字节
都不动**——历史前缀不变，网关的提示缓存才命中得上。设计扇出那种一轮就完的会话关掉压缩。

## 5. 每轮快照与撤回

- 每一句开工前拍一张（`/agent/ask` 里），记下这一刻有几条消息、用户说了什么。
- 按内容寻址：每个文件按 sha256 存一份 blob，快照只是一页「路径 → 哈希」。没变的文件所有快照共用，
  工作区里躺着几张 2 MB 的生成图也不会每轮复制一遍。不用硬链接——`write_file` 是原地截断重写，
  硬链接会让快照跟着被改掉。
- 存在工作区**外面**（`.ispace/snapshots/{工作区}`）：不能跟着发布出去，也不该出现在文件树里。
- 不管 `node_modules`、`.git`、顶层 `_` 草稿（撤回时把扇出的六版也删了，人会以为扇出坏了）。
- 每个工作区留 30 张，没人引用的 blob 一并清。
- `POST /agent/undo`：文件退回、对话截回、用过的快照删掉——连点就一步步往前退。只退文件不行：模型还
  记得自己"已经把标题改成红色了"，下一句会接着一个不存在的改动说。前端把被撤掉的那句话放回输入框。

## 6. screenshot_preview

- 截图器是现成的：发布时自动补封面的那个 chromium（`cover-shot.ts`），这里换了目标（工作区）和尺寸
  （手机 390×844 / 电脑 1280×800）。带 `--allow-file-access-from-files`，否则 module 脚本跑不起来。
- 和生图一样**有才挂**：机器上没有 chromium（本机 dev）就不挂工具、提示里也不提。
- 图不能放进 `role: tool`（协议只收文本），也不能插在两条工具结果中间；会话循环等这一轮的工具结果全部
  回灌完，再补一条带图的 user 消息，并注明"平台自动附上的，不是用户发的"。
- 盲区写在工具说明里：截的是本地文件，取数区域为空、根绝对路径加载不到——不写的话模型会去改一段本来
  没问题的代码。

## 7. 对话流与多格式附件

- **气泡**：用户在右、实底；模型在左、带头像、白底卡片。来回几轮之后人往回翻，一眼分得清。
- **Markdown**：`md.ts` 自己解析成树、渲染全走 React 元素，没有一处 innerHTML——模型的回话会复述用户贴进
  来的东西，里面完全可能有 `<img onerror=…>`。链接只放行 http(s)、mailto、相对路径。流式输出时没闭合的
  代码块也能画。
- **附件**：`files` 走 `/agent/ask`（这一条路的请求体上限放到 32 MB，其余仍是 1 MB），存进 `_uploads/`
  （发布链路排除、快照不管、搜索默认跳过）：
  - 图片：照样作为多模态图片发给模型
  - md/txt/csv/json：原文
  - Word / Excel / PPT：服务端读 zip 抽文字（段落 / 单元格按表 / 每页文本框），不引 office 库——附件是
    不可信输入，只解压认识的几个条目、每个上限 8 MB 防 zip 炸弹
  - PDF：**读不出文字**（不引库读不准），明确告诉模型"这是个 PDF、平台读不出来"
- **预览**：图片缩略图点开放大，md 按 Markdown 排，PDF 用浏览器阅读器，Office 给下载。原始字节走
  `GET /agent/workspace/raw`：同源伺服不可信文件，所以只有图片、PDF、纯文本内联，HTML/SVG 一律 attachment，
  带 nosniff。模型生成的图也直接摆进对话。
