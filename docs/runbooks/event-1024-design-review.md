## 二、脚本比对查出来的（你没提，但稿和实现不一致）

把稿里所有 `.ev-*` 规则抽出来和 `styles.tsx` 逐条比，查出 61 处。
按小节重建了整份样式表。主要的：

**初筛 / 打分两栏**（改动最大）
稿上这两栏是**横排**：标签固定宽（初筛 60px、打分 72px）+ 说明占剩余 +
一根引导虚线 + 右端分值。我原来做成了竖排（标签一行、说明一行），
分值用 grid 对齐。字号也差一档（稿 14px，我 12–13px）。已按稿改成 flex 横排。

**参赛规则**
序号稿上是 24px 粗体、宽 40px 的大号数字，我做成了 12px 的小灰字；
正文 14px（我 13px）；标题区 padding `22px 24px 20px`（我 `26px 0 0`）。已对齐。

**其余**
- 评委卡：`gap` 24（我 16）、`padding` `24px 22px 28px`、底部要有一条分隔线（我没有）
- 两栏之间的竖线：稿是 `1px solid var(--border-subtle)`，我用了 `1px dashed var(--border-hover)`
- 领奖台三张卡加 `order: 1/2/3`（塌成一列后一等奖排最前）
- 日程两栏的错位起始高度，稿上包在 `@media (min-width: 901px)` 里，我写成了无条件
- 小节说明 `text-align: center`、小节标题 `font-family: var(--font-sans)`
- 阶段卡背景稿上是 `rgba(255,255,255,.8)` 半透明，我用了不透明的 `--surface-1`
- 奖牌图三张在 v6 里换过，已重新拷贝

**比对脚本有个坑，说一下**：同名选择器如果在媒体查询里又出现一次，
我第一版脚本会用媒体查询的值覆盖基础值，于是漏报。所以最后不是逐条打补丁，
而是把稿的整段基础规则导出来重建了样式表。

## 三、我还补了一处稿里有、之前整个漏掉的

**指针比特场**（`BitField.tsx`，新文件）

稿里 hero、内容区、腰带各挂了一层 canvas：鼠标走到哪，那一圈的 0/1 就亮起来，
离开后衰减熄灭。你发的第一张截图里 hero 右上角那些若隐若现的 0/1 就是它。
我之前完全没做。现在照稿的算法移植了，三处都挂上，参数也照稿
（hero/腰带白字白光、内容区橙字橙光，腰带半径 120 其余 150）。

实现上注意了三点：指针事件挂父元素（canvas 自己 `pointer-events:none`，
否则吃掉按钮点击）；热度全衰减到 0 就停 rAF，不空转；
`prefers-reduced-motion` 直接不启动。

## 四、刻意和稿不一致的地方（请你拍板）

这几处是我判断后故意没照抄的，都可以改回去：

**1. 手机上的左右留白**
稿里内容列恒定 `padding: 0 40px`，没有任何断点。375 的手机上两边各吃掉 40，
只剩 295 可用。这一页主要是转发到群里用手机点开的，所以我在 720 以下收到了
16px。**如果要严格照稿，把 `styles.tsx` 里 `.ev-page` 那条媒体查询删掉即可。**

**2. 窄屏的点阵尺寸**
稿里点阵恒为 13px 格子（整块 365px 宽），窄屏靠裁切——你给的那张窄屏截图
实测是 701px 视口（2x 导出），公式那行就是被右边裁掉的。701 上这样没问题，
标题还在；但到 375 的手机上，365px 的点阵会把「程序员节」整个挤出屏幕。
我分了三档：>720 用 13px（和稿一致）、480–720 用 9px、<480 用 6px。
**代价是 701px 那一档比稿小一圈。**

**3. `#606266`**
稿里参赛规则正文用了这个灰，平台 token 里没有完全等值的。
最接近的是 `--text-secondary`（`#545659`），肉眼分不出，按仓库惯例用了 token。

**4. `.ev-content-dark` 没实现**
稿把内容区包了一层，用途是把浅色 token 钉死、不跟随外层主题。
portal 目前没有深色主题，且那一层钉的值（`--text-heading:#001217`、
`--border-subtle:rgba(0,0,0,.06)` 等）和我们 token 的现值**完全相同**，
所以是空操作。将来 portal 要上深色主题，这一层得补。

**5. `.tby-card` 那几条覆盖没实现**
稿是在 Tabby 的 Card 组件上做覆盖，我们没用那个组件，等价样式直接写在
`ev-*` 上了。视觉等价。

**6. 文案里的数字一律走 config/stats**
稿上是写死的演示值（「收到 42 个创意」之类）。照抄会出现实际 7 个却显示 42。
措辞照稿，数字和日期全部从接口算。

**7. 蛋糕印刷稿没做**
`1024 蛋糕图.dc.html`、`1024-poster-digital.dc.html` 都没实现——上一轮你明确说
蛋糕图不要做。海报那份没提过，目前也没做。

## 五、评委打分页与两块大屏（补做）

**先澄清一件事**：v6 里 `1024 评委打分.dc.html` 从 358 行涨到 617 行，
但那 259 行净增**几乎全是颁奖大屏被并进了这个文件**——v5 时它是单独一份。
打分页本身只动了两行。所以「改动很大」是个假象。

**打分页**
结构本来就是对的（左侧路演顺序列表 + 右侧详情 + 四个滑块 + 总分 + 提交），
`WIDE = 900` 的两栏/单栏切换、锁定态、「其他评委 N/M 已提交」都在。
按稿补了一处：列表行的状态原先只靠颜色区分（绿=已提交、橙=有草稿），
现在照稿写明文字——已提交给「分数 + 已提交」，打了没交写「未提交」，
没动过写「未打分」。光靠绿橙两色分辨「交没交」，色弱的人看不出来，
而这一步不可逆。

**颁奖大屏**
文案按 v6 对了三处：
- 开场屏改成稿的三行（`10.23 · 大培训教室 · 15:10` / 颁奖典礼 /
  `N 件入围作品 · M 位评委 · 三个奖项依次揭晓`），日期地点人数全部从数据算
- 揭晓屏的「评委平均分」→「评委综合分」
- 收尾的「感谢评委」→「感谢 N 位评委」，人数走数据

**背景墙大屏**
与稿一致，无需改动。v6 新增的 `assets/soyoung-icon.png` 其实是
v5 的 `soyoung-logo.png` 改了个名（MD5 一致），我们这边早就是对的。

## 六、确认做不了的

**1. 线上评委是 0 位（最要紧）**
没有任何迁移灌过 `event_judges`，`0017` 只建了表。后果：活动页「评委 · N 位 TL」
那张卡不显示，`/1024/judge` 对所有人都会拒。10.19 初筛前必须先配 8 位 TL。
我没有这 8 个人的账号，得你给或者在赛事管理页加。

**2. 打分页的「正在路演」标记 —— 决定不做**
稿上列表里有一个「● 正在路演」的状态，标记此刻正在台上的那个项目。
要做它得先加字段，再给主持人一个「现在轮到 NO.04」的控制入口，还得保证
路演过程中有人一直盯着点——是个功能，不是样式。

10.16 与用户确认：**不做**。代码里本来也一处都没有（`isLive` / `onStage` /
`正在路演` 全仓库零命中），所以无需移除，只是从计划里划掉。

打分页列表因此是三个状态：已提交 / 未提交 / 未打分。评委靠左侧列表的
编号顺序自己对齐台上的项目——编号就是路演顺序，这一点在页面上写着。
